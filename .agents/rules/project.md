# Xiaomi Master Camera Combo — правила проекта

Этот файл читается агентом автоматически. Здесь только то, что нельзя
угадать из кода: устройства, базы камер и грабли, на которых уже спотыкались.

Подробные процедуры лежат в навыках: `.agents/skills/`.

---

## Что это за проект

Модификация системной камеры Xiaomi. Агент заменяет `MiuiCamera.apk` и
сопутствующие ресурсы, упаковывая всё в модуль Magisk / KernelSU / APatch либо
в standalone APK для Core Patch.

Автор сборок: `borndead`. Репозиторий: `bjorndith-cmd/Mi_Master_Camera_Combo`.

## Устройства

Кодовое имя определяет всё: какой XML грузится, какая карта сенсоров, какие
зумы доступны. Ошибка в кодовом имени ломает камеру полностью.

| Кодовое имя | Модель | Основной сенсор | Телеобъектив | Перископ | Широкоугольный | Зум |
|---|---|---|---|---|---|---|
| `ishtar` | Xiaomi 13 Ultra | Sony IMX989 | IMX858 3.2x | IMX858 5.0x | IMX858 0.5x | 0.5:1.0:3.2:5.0 |
| `aurora` | Xiaomi 14 Ultra | Sony LYT-900 | IMX858 3.2x | IMX858 5.0x | IMX858 0.5x | 0.5:1.0:3.2:5.0 |
| `dada` | Xiaomi 15 | Light Hunter 900 | Samsung JN5 3.2x | нет | Samsung JN1 0.6x | 0.6:1.0:3.2 |
| `haotian` | Xiaomi 15 Pro | Light Hunter 900 | нет | IMX858 5.0x | Samsung JN1 0.6x | 0.6:1.0:5.0 |
| `xuanyuan` | Xiaomi 15 Ultra | Sony LYT-900 | IMX858 3.0x | **Samsung HP9 200 Мп** 4.3x | Samsung JN5 0.5x | 0.5:1.0:3.0:5.0 |
| `nezha` | Xiaomi 17 Ultra | OmniVision OVX10500U | 50 Мп 3.0x | **Samsung HP9 200 Мп** 5.0x | 50 Мп 0.5x | 0.5:1.0:3.0:5.0 |

Переменная диафрагма: у `ishtar` F1.9/F4.0, у `aurora` F1.63/F4.0 (плавная), у
`xuanyuan` и `nezha` есть. У `dada` и `haotian` — нет. **Заявлять переменную
диафрагму на устройстве без неё нельзя** — камера падает при попытке управления
ирисом.

XML-файлы наследуются цепочкой. Например `haotian` тянет `haotian.xml` →
`dada.xml` → `ishtar.xml`, а `nezha` → `xuanyuan.xml` → `ishtar.xml`. Отсюда
`ishtar` присутствует у всех как базовый.

Полный машинный список: `configs/devices.json`.

## Базы камер

Три базы в обращении. Выбор базы — главное решение при сборке.

| База | versionCode | Собрана под | Где применяется |
|---|---|---|---|
| **Universal 5.0 Beta 8.3** | `599830000` | Android 11 (API 30) | основная, 12 архивов |
| **6.8.001960.0** | `680019600` | Android 16 (API 36) | только 13 Ultra |
| HOLYBEAR-5.2.001450.2 | `1520014502` | Android 13 (API 33) | чужая ветка, 2 архива |

**Важно:** Universal 5.0 Beta 8.3 собрана под API 30, но ставится на Android
15–16. Она работает, но это камера эпохи Android 11 — при странностях на новых
системах причина может быть именно в этом, а не в конфиге.

Новые базы искать здесь:
`C:\Mi_Master_Camera_Combo\Freebuff\workspace\` — файлы вида
`MiuiCamera_v5X_aligned.apk` (число после `v` — версия: `v58` = 5.8,
`v59` = 5.9, `v60` = 6.0).

## Грабли, на которых уже спотыкались

### 1. CRLF в шелл-скриптах — модуль не устанавливается

Самая дорогая ошибка. Если `customize.sh`, `service.sh` или `post-fs-data.sh`
содержат окончания строк Windows (`\r\n`), Android-оболочка их не разбирает:

```
customize.sh: line 43: syntax error: unexpected word (expecting "do")
! Installation failed
```

Внешне выглядит как «модуль несовместим с Android», хотя версия системы тут ни
при чём. Ломается ещё и разбор `\`-переносов строк — в логах появляется мусор
вида `configsaurora.json` вместо `configs/aurora.json`.

**Всегда проверять окончания после упаковки.** Процедура — в навыке
`package-magisk-module`.

### 2. Подмена кодового имени ломает чужие устройства

В старых скриптах сборки (`build_v56_master.py:563`, `build_v57_master.py:229`)
есть строка:

```python
resetprop ro.product.device "ishtar"
```

Модуль объявляет систему 13 Ultra на любом устройстве. На 15 Ultra камера
грузит карту сенсоров от 13 Ultra и уходит в аварийный режим — кадры теряются,
снимок сохраняется в 1.5 Мп.

**Не подменять `ro.product.device`.** Устройство должно оставаться со своим
именем.

### 3. `aapt2` не читает часть сборок

На `Mi13U_Camera_6_v8.2_by_borndead.apk` команда `aapt2 dump badging` молчит и
возвращает ошибку. Старый `aapt` из того же набора читает нормально.

Оба лежат в `E:\Android\Sdk\build-tools\35.0.0\`. Если `aapt2` не дал версию —
пробовать `aapt`, прежде чем делать вывод, что APK битый.

### 4. Имя файла камеры различается по регистру

В части сборок APK внутри модуля называется `MIUICamera.apk` — заглавными `UI`.
В остальных `MiuiCamera.apk`. Скрипты и распаковка, где путь прописан вручную
как `MiuiCamera.apk`, на таких архивах не находят камеру.

**Не прописывать путь вручную.** Брать имя записи из оглавления архива:

```powershell
$entry = tar.exe -tf $zip | Where-Object { $_ -match '(?i)MiuiCamera\.apk$' } | Select-Object -First 1
tar.exe -xf $zip -C $tmp $entry
```

### 5. Нулевой размер файла = не развернулся Git LFS, а не потеря содержимого

Все `.zip` и `.apk` в проекте хранятся через Git LFS. Если фильтр не сработал
при checkout, рабочий файл остаётся нулевым, хотя содержимое лежит в
`.git\lfs\objects`. **Пересобирать ничего не нужно** — файл восстанавливается
копированием объекта по `oid` из указателя.

Семь файлов в `releases\` так и выглядели нулевыми и были успешно
восстановлены. Подробная процедура — в навыке `verify-camera-base`.

Причина сбоя фильтра — невозможность создать именованный канал
(`fatal: could not create signal pipe, Win32 error 5`). Внутри ограниченной
песочницы это ожидаемо; вне неё LFS работает.

### 6. Git LFS не работает локально

`git status` падает:

```
error: could not read greeting from subprocess 'git-lfs filter-process'
fatal: releases/...apk: clean filter 'lfs' failed
```

Файлы на месте, но команды, читающие рабочее дерево, ломаются. Причина —
Git LFS не может создать канал связи на этой Windows.

## Как писать для тестеров

Тестер учится и не знает тонкостей.

1. Нумерованные шаги, каждый — одно действие.
2. Указывать, куда нажимать: «долгое нажатие → Вставить», «Enter».
3. Писать, что человек увидит на экране после шага.
4. Команды — готовыми блоками для копирования, не по одной.
5. Возможные ошибки — таблицей: что на экране → что делать.
6. В конце — что прислать в ответ.

Инструкция пишется под чистое состояние: сначала полная очистка и перезагрузка,
потом установка, потом проверка. Иначе результат относится не к той сборке,
которую тестируют.

**Напоминать про удаление обновлений стоковой камеры** перед установкой:
Настройки → Приложения → Камера → Удалить обновления. Без этого модуль
конфликтует со стоковой версией.

## Как указывать файлы в ответах

Рядом с именем файла всегда печатать полный путь:

```
Mi15U_Master_Camera_Combo_5_v6.4_A16_Final.zip
C:\Mi_Master_Camera_Combo\github_sync\releases\Mi15U_Master_Camera_Combo_5_v6.4_A16_Final.zip
```

Одного имени недостаточно — файл из чата не открывается.
